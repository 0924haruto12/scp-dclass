# NEED TO KNOW 歩調縦切り 実装メモ

版: slice-pacing-1 · 2026-10-25 · 対象仕様: [MVP仕様案 draft 0.1](../design/NEED_TO_KNOW_MVP仕様案.md)

MVP仕様案11節の手順2「歩調の操作縦切り」と、手順3「1日＋死亡継承」の土台を実装した。仕様案は採否未確定のままで、この実装も仕様の採択を意味しない。数値はすべて仕様案の仮置き値で、人による検証はしていない。

## 範囲

| 実装したもの | 内容 |
| --- | --- |

## 構成

エンジンと対象OSは未決のため、ブラウザで動く試作として作った。判定はすべて `src/core/` の純TypeScriptにあり、DOM・Canvas・音に依存しない。エンジンを選定した後も、ルールとテストをそのまま移植・照合できる。

| パス | 役割 |
| --- | --- |
| `src/core/pacing.ts` | 歩調の状態機械。1/60秒の固定刻みで、時計は刻み数で数える |
| `src/core/runner.ts` | 実時間から固定刻みへの変換。ポーズ・ノート・設定・フォーカス喪失で停止 |
| `src/core/cycle.ts` | 施設サイクル、被験者、朝・召集・実験・聴取・事後・夜・死亡報告の遷移 |
| `src/core/ledger.ts` / `interrogation.ts` | 信用・疑念の加減点と聴取 |
| `src/core/notebook.ts` / `reports.ts` | ノート、封筒、記憶処理、事後報告書 |
| `src/core/presentation.ts` | 1つの出来事から音・字幕・画面表示を作る |
| `src/core/save.ts` | 保存・読込・破損データの退避 |
| `src/game/` | ブラウザ側の入力、Canvas描画、Web Audio合成音、画面 |
| `tests/` | 受入条件ごとの自動テスト |

## 仕様の解釈

仕様案に書かれていない点は、次のように決めた。プレイテストの結果次第で見直す。

1. **後退中の再接近は危険時計を0から数える。** 仕様案3.2の「前兆提示後に最低2秒の猶予」を守るためである。代わりに、走る→0.5秒止まる→走る、を繰り返す断続走行が成立する。速すぎる攻略になっていないかは人による検証で確かめる。
2. **負荷指示の達成条件。** 帰路で赤線から1単位以内で走り始め、途切れずに青線まで走った場合に達成とする。途中で走行をやめると、その試行は無効になる。もう一度赤線の手前から走り直せる。
3. **接近中は出口の扉が開かない。** 未解除の危険を持ったままの生還を防ぐためである。後退・追従の状態なら退出できる。箱を持たずに扉に触れると、インターホンが1回だけ回収を促す。途中で退出する手段は設けていない。
4. **明示的な拒否は、後で指示を達成してもC-1とする。** 仕様案6.2の「明示的な拒否と…未達はC-1」に従った。
5. **聴取の「足音が重なったので止まりました」は、その試験で足音の重なりまたは接近を聞き、かつ停止・後退を経験した場合だけ選べる。** 観測していない経験を説明する選択肢は出さない。
6. **「全部知っています」は、根拠となる観測がある場合はSを変えない。** 仕様案は根拠なしの場合（S+1）だけを定めている。床の擦り跡やカメラの確認は、異常の根拠に数えない。
7. **研究員の発話は、字幕設定によらず常に文字で表示する。** 音声素材がないためである。字幕設定は足音などの効果音にだけ効く。前兆音は研究員の声で弱めない。
8. **封筒の中身は、読んだ人物の伝聞カードになる。** 話者は「寝台下の封筒（筆跡）」とする。観測カードとしては移さない（仕様案2.3）。
9. **清掃業務（安全な追加業務）は、どの夜でも行える。** 1日1回だけC+1・S-1になる。仕様案8.1の6日目の監督用名札は未実装。
10. **追従者の位置は、被験者が最後に動いた方向の背後に置く。** 姿は描かず、足音の方向と埃の位置だけに使う。被験者が向きを変えると瞬時に反対側へ移るが、判定には影響しない。
11. **世界観の固有名は避けた。** SCP名義か独自組織かが未決のため、画面には「区画」「D-番号」「研究員」だけを出す。

## 既知の制約

- 操作はキーボード＋マウスのみ。キー割当は `src/game/input.ts` の `KEYMAP` にまとめてあるが、画面からは変更できない。
- 合成音は仮のもので、方向は左右のパンだけで示す。前後の区別は字幕と画面上の弧に頼る。
- 保存はブラウザの localStorage。破損データは `need-to-know.save.corrupt.<時刻>` に退避する。
- `?dev` を付けて開くと、F3で開発用ログ（許容速度、危険時計、C/S/E、seed）を表示する。通常画面には数値を出さない。
