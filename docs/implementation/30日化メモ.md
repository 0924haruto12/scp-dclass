# 30日化メモ

版: thirty-day-1 / 2026-10-26 / 基点: `b69eaa2`（統合プロトタイプ）

対象: 統合プロトタイプを7日間MVPから**1ラン30日**へ拡張した実装記録。

これは、利用者から「30日間まで遊べるところまで実装して」と指示されて実装したものである。[MVP仕様案](../design/NEED_TO_KNOW_MVP仕様案.md)は、人によるプレイテストが完了してから30日化へ進む順序を示している。この実装はその順序を仕様の採択として置き換えるものではない。人による30日間の通しプレイテストは未実施である。

## 1. 今回の到達点

- 30日分の固定割当表を追加し、1日目の朝から30日目の終了判定まで遷移できるようにした。
- 既存4異常（歩調・名札・給水器・白い扉）を反復して30日を構成した。新しい異常・試験室は追加していない。
- 死亡時は日付だけを1日進め、次の被験者へ封筒と施設パラメータを引き継ぐ既存仕様を30日目まで延長した。
- 給水器を2日目・12日目・22日目に再設置し、各設置回を別の遅効イベントとして扱うようにした。
- 役割評価Eの機会を16日目と30日目（いずれもT-101）に置いた。同一人物が両方を完了しないとE=2にならない。
- 監督用名札の支給機会を29日目の夜へ移し、30日目の朝の脱走未遂分岐へ接続した。
- 30日目の終了判定を既存の優先表（脱走未遂 > 最終日死亡 > 有用認定 > 標準処分）のまま適用した。
- 旧7日間サイクルの保存データを、日付・被験者・封筒・事後報告履歴を保持したまま30日スケジュールへ移行する処理を追加した。
- UIの日付表示・期表示・給水器パネル・最終日脱走ボタン・死亡報告・夜の特別条件を30日仕様へ更新した。
- 新サイクル開始時の施設コード採番（`SITE-19-C01` → `SITE-19-C02`）を修正した。旧実装は数字を連結して`C1902`になっていた。

## 2. 30日日程

| 日 | 割当の原則 |
| --- | --- |
| 1〜29日目 | `T-101` → `T-204` → `T-309` の3室巡回。担当官は初回7日間の配置パターンを繰り返す |
| 30日目 | 最終回収として`T-101`を固定。`isFinalDay` |
| 16日目 | 指定評価業務 #1（T-101、E+1条件） |
| 29日目 | 夜の安全な再評価業務が監督用名札の支給機会 |
| 30日目 | 指定評価業務 #2（T-101、E+1条件）＋最終評価 |

- 第1期（1〜10日）は観察の時期で、基本操作と前兆を学ぶ。
- 第2期（11〜20日）は接触の時期で、同じ室の再割当と記録の照合を行う。
- 第3期（21〜30日）は月末で、脱走・有用認定・処分の分岐が近づく。

日程は`src/core/content.ts`の`THIRTY_DAY_SCHEDULE`で固定している。ランダム割当は採用していない。異常の変動パラメータは従来どおりサイクル開始時に固定し、日ごとには再抽選しない。

## 3. 給水器の再設置

- 設置日: 2日目、12日目、22日目。
- 各設置回の飲用は`water-drink-d{設置日}-{被験者ID}`で記録し、設置回ごとに1回だけC+1。
- 遅延日数はサイクル固定パラメータ（2日または3日）を使う。設置日を`I`とすると、`I + delay`日の夜に複製が現れ、`I + delay + 1`日の朝に比較面接を行う。
- 死亡した被験者の予約イベントは従来どおり取り消し、次の被験者へ効果を移さない。
- 設置日以外は共用室の給水器パネルを表示しない。

## 4. 終了判定

| 優先 | 条件 | 結果 |
| --- | --- | --- |
| 1 | 30日目の朝、監督用名札で外門の検問まで進む | 脱走未遂 |
| 2 | 30日目に現被験者が死亡 | 処分・欠員補充停止 |
| 3 | 最終業務を生還し、E=2、C>=2、S<=1 | 有用認定 |
| 4 | その他の30日目終了 | 処分 |

- 有用認定のE=2は16日目と30日目のT-101で目的物を生還搬出した場合に各+1される。死亡交代した人物はE=0から始まるため、両方を同一人物で満たす必要がある。
- 29日目の夜の安全な再評価業務は、完了後の値がC>=2かつS<=1なら監督用名札（`SUP-30`）を支給する。28日目以前の同じ業務では支給しない。
- 30日目の死亡は、生前のE/C/Sが認定条件を満たしていても優先2で終了する。

## 5. 保存データの移行

`src/core/storage.ts`で読み込み時に次を行う。

- `cycle.day`の許容範囲を1〜30へ拡張。
- 旧7日間スケジュール（7件）を検出したら、30日スケジュールへ置換。
- 旧保存に`waterCoolerInstallDay`がない場合は、既存の`waterCoolerPresent`から補完。
- `cycle.version`を`0.2.0-30d`へ更新。
- 移行した事実を行動ログに残す。日付・被験者・封筒・事後報告履歴・固定パラメータは保持する。

破損データの保護（AC15）と、実験中2秒ごとの自動保存・ポーズ復元（AC03）は従来のまま維持している。

## 6. 検証

確認日: 2026-10-26。Node.js v24.21.0、Chromium 153（Playwright）。

| コマンド | 結果 | 範囲 |
| --- | --- | --- |
| `npm test` | PASS 28件 | AC01〜AC15の15件、保存障害3件、30日ラン10件 |
| `npm run build` | PASS | `tsc --noEmit` と Vite本番ビルド |
| `npm run test:browser` | PASS 13項目 | 30日表示、第1期表示、最終日脱走ボタン→終了画面、既存の保存・レイアウト・コンソール検証 |
| `npm run test:30day` | PASS 4項目 | 1日目から30日目までを画面操作で通し、最終T-101生還後に有用認定（E=2, C=3, S=0）へ到達。ページ例外0件 |

30日ラン用テストの確認項目は次のとおり。

1. 30日スケジュールの全日・期・評価日・給水器設置日・最終日の整合。
2. 死亡せずに30日目まで進み、16日目と30日目の評価を同一人物で完了すると有用認定になること。
3. 29日目の死亡で30日目朝へ進み、30日目の死亡で欠員補充停止になること。
4. 28日目夜には監督用名札が支給されず、29日目夜だけ支給され、30日目朝に脱走未遂へ進めること。
5. 12日目の給水器再設置と、所定の朝の比較面接解決。
6. 給水器の比較面接が設置回ごとにC+1の安全応答を与えること。
7. 旧7日間保存の30日スケジュール移行と日付・被験者・封筒の保持。旧E・旧監督用名札の無効化、旧給水器キーの移行を含む。
8. 既に30日スケジュールへ移行済みの保存でも、16日目・30日目以外のE記録を正規化し、有用認定を迂回できないこと。
9. 中間版の正当な29日目監督用名札は引き継ぎ、支給記録のない名札は無効化すること。
10. 30日終了後の新サイクル開始で日付が1日に戻り、施設コードが`C01`→`C02`になること。
