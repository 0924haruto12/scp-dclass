これは4モデルが並行実装した試作を1本に整理した記録である。仕様案の採択、受入条件の一括合格、人によるプレイテストの完了を意味しない。

## 1. 統合の方針

4本は同じ `README.md`・`index.html`・`package.json` をそれぞれ独立に作り直しており、Gitのマージでは統合できない。そこで次の形を取った。

- **土台**: Antigravity版（`t3/start-implementation-1` / `b036e16`）。7日間MVP、異常4種、終了分岐、AC01〜AC15のテストを持つ唯一の実装。
- **他3本**: コードやUIは混ぜず、移植可能な検証手法・保存保護・実装記録だけを取り込む。
- **元ブランチ**: 削除せず、比較資料として残す。比較表は[ブランチ比較](ブランチ比較.md)。

## 3. 統合時に直したもの

| 変更 | 理由 | 根拠 |
| --- | --- | --- |
| 実験中2秒ごとの自動保存 | 土台は実験開始時しか保存せず、再読み込みで位置・残り時間・警告経過が失われていた | AC03。ブラウザ検証で再現・修正 |
| `pagehide` / `visibilitychange` での保存とポーズ | 再読み込み・タブ非表示時に保存されない経路があった | AC03 |
| 復元時の「実験を再開」バナー | 土台は再開手段が分かりにくく、停止したまま操作できなかった | AC03の操作受入 |
| 保存領域の例外処理 | `localStorage` の容量超過・読取不能でゲームが例外終了する可能性があった | AC15。容量エラーを模したテストを追加 |
| 破損データ退避の成功確認 | 退避に失敗しても保存枠を消していた | AC15。失敗時に元データを保持するテストを追加 |
| favicon 404の解消 | ブラウザ検証でコンソールに404が出ていた | コンソール例外0件の確認 |

## 5. 統合しなかったもの

- Claude版・OpenCode版・Codex版のコードとUI。APIと画面構成が異なり、部分マージは全面改修になるため。
- Claude版の練習モード、Codex版のタブ間保存競合の検出、OpenCode版の詳細な仕様解釈メモ。必要になった時点で個別に移植する。
- 各ブランチのテストスイート。対象APIが異なるため、考え方だけを取り込み、テストは統合版のAPIで書き直した。
- 各ブランチのREADME・実装メモ。履歴として元ブランチに残し、本書で要約した。
